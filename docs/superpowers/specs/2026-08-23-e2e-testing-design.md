# E2E-проверка English Meet Bot

Дата: 2026-08-23

## Цель

Дать Кириллу два инструмента проверки корректности бота:

1. **Ручные e2e-сценарии** — чеклисты для прогона в реальном Google Chat
   (там, где нужен живой чат, карточки, кнопки и проактивные DM).
2. **Автономные e2e-тесты** — pytest-тесты, которые шлют настоящие HTTP-запросы
   в поднятый `uvicorn` и проверяют ответ + состояние БД.

## Решения (согласовано)

- **Окружение автономных тестов**: реальный HTTP против `uvicorn` на
  `localhost:8000` (не ASGI in-process). Максимально похоже на прод.
- **Форма**: pytest-тесты с маркерами, а не standalone-скрипты.
- **Live-тесты**: отдельная группа, реально дергающая Google Chat API через
  сервисный аккаунт (отправка в тестовый space).
- **LLM live-тест**: один реальный вызов OpenRouter (по явной команде), т.к.
  генерация платная и медленная. Юнит-покрытие с моком уже есть.

## Артефакты

### 1. Ручные сценарии — `docs/e2e-scenarios.md`

Чеклисты S0–S8. Каждый: предусловия → шаги → ожидаемый результат → что проверить в БД.

| # | Сценарий |
|---|----------|
| S0 | Подготовка окружения (ngrok, `.env`, поднятие БД+бота) |
| S1 | Онбординг нового участника |
| S2 | Добавление бота в группу (DM vs @mention) |
| S3 | Ежедневный опрос — полный цикл (9:00 → голос → 14:05 финализация) |
| S4 | Еженедельный вопрос: LLM + fallback на банк |
| S5 | ENG-7: приглашения, пост в Space, напоминание T−1ч, окно check-in |
| S6 | Check-in «Я на встрече ✅» внутри/вне окна |
| S7 | Broadcast-рассылка в DM |
| S8 | Негативные: битый JWT, невалидное время, пустая анкета, сабмит после дедлайна |

### 2. Автономные тесты — `tests/e2e/`

| Файл | Содержимое |
|------|------------|
| `conftest.py` | фикстуры: async HTTP-клиент, сессия БД, очистка тестовых данных |
| `test_health.py` | `GET /` и `GET /api/v1/health` |
| `test_webhook_onboarding.py` | анкета (buttonClickedPayload) → 7 ответов; повтор → история растёт |

## Маркеры и запуск

```powershell
pytest -m e2e    # локальные (HTTP + БД), без Google
pytest -m live   # реальная отправка в Chat + реальный LLM
pytest           # только юниты (e2e/live отключены через addopts)
```

- `pytest.ini`: `addopts = -m "not e2e and not live"`, `asyncio_mode = auto`.
- Зависимости: добавить `httpx` (уже в venv) и `pytest-asyncio` в `requirements.txt`.

## Ограничения (принятые)

- **Scheduler-часть** (финализация 14:05, напоминание T−1ч, окно check-in) не имеет
  HTTP-эндпоинта — проверяется прямым вызовом функций джобов
  (`finalize_daily_poll`, `handle_time_finalized`, `submit_checkin`) с проверкой
  эффектов в БД и в стабе отправки.
- **Проактивная отправка** в автономных e2e проверяется стабом
  (`messaging.send_message` уже падает в стаб без реального Chat); реальную
  отправку покрывают live-тесты и ручные сценарии S5–S7.
- **Ежедневный опрос** в `submit_poll` жёстко привязан к `today()`, поэтому e2e-тест
  опроса работает с реальной датой: в setup сбрасывает/создаёт опрос дня
  (как `scripts/test_poll_flow.py`) и чистит только свои записи (`users/e2e_*`).
- Тесты изолированы префиксом `users/e2e_` и чистят за собой в teardown.

## Готово, когда

- `pytest` — все юниты зелёные (e2e/live не трогаются).
- `pytest -m e2e` при поднятом `uvicorn` — все локальные e2e зелёные.
- `pytest -m live` — live-тесты проходят (или честно скипаются при пустом space/ключе).
