# Дизайн: недельная тема, вопросы недели, запрет прошедших дней, план карточки

- **Дата:** 2026-08-26
- **Статус:** на ревью
- **Тип:** architectural (4 связанных изменения в существующих флоу)

## Цель

1. Сделать еженедельные вопросы разнообразнее и без повторов, с осмысленным базисом генерации.
2. Запретить голосовать за прошедшие дни недели.
3. Сделать карточку занятия явным «планом урока» (вводная / основная / конец), контент меняется от типа карточки.

## Ключевые решения (утверждены)

- **Тема недели** выбирается **автоматом** (ботом), не людьми.
- Персональный вопрос генерится вокруг **темы недели + интересов + уровня**.
- Второй вопрос остаётся **общим** для всех, но **без повторов**.
- Карточка — **фиксированный 4-фазный план**: Warm-up → Main → Stretch → Wrap-up.

## Недельная тема (стержень)

- Новый модуль `app/services/week_theme.py`:
  - `THEME_BANK: list[str]` — ~24 курируемых широких тем (Travel, Food, Work-life balance, Technology, …).
  - `week_theme(week_start: date) -> str` — детерминированная ротация по ISO-номеру недели (без хранения, без повтора в пределах банка).
- Используется в двух местах:
  - **вопросы** (воскресенье) — тема для персонального вопроса;
  - **карточка** (позже в ту же неделю) — тема как топик занятия.
- Детерминированность по `week_start` гарантирует согласованность вопросов и карточки без нового хранилища.

## Изменения данных

- Новых колонок/таблиц/миграций нет. Банк тем и банк вопросов — константы в коде.

## Компоненты

### 1. Вопросы недели

- **Персональный**: `generate_personal_question(..., theme)` — промпт строится из `тема + интересы + уровень + avoid` (прошлые вопросы и прошлые темы).
- **Общий (второй)**: банк `BANK` расширяется до ~52, ротация детерминированная по ISO-неделе (не повторяется ~год). Остаётся одинаковым для всех.
- `questions_for_profile(interests, week_start, level, avoid, theme)` — прокидывает тему в персональный вопрос; общий — из банка.
- `send_weekly_questions` передаёт `week_theme(week_start)`.

### 2. Запрет прошедших дней

- **Сервер** (`submit_poll`): после `_normalize_submit` — если `day < today.weekday()` (таймзона `app_timezone`) → `{"ok": False, "reason": "past_day"}`.
- **Карточка** (`build_weekly_poll_card`): для прошедших дней не рендерить кнопки времени, показать `— passed` (сегодня остаётся голосовабельным).
- Таймзона — `get_settings().app_timezone`, не UTC.

### 3. Карточка: 4-фазный план

Структура `content` становится явным планом с таймингами:

| Фаза | Поле | Тайминг |
|------|------|---------|
| Warm-up | `warm_up` | ~5 мин |
| Main | `main_content` (топик = тема недели + `type_specific_payload` + подвопросы) | ~20 мин |
| Stretch | `stretch_challenge` (сейчас всегда `None` — заполняем) | ~10 мин |
| Wrap-up | `wrap_up_question` | ~5 мин |

- `stretch_challenge` — type-aware усложнение (debate → опровержение, storytelling → сюжетный поворот, topic → вопрос посложнее, …).
- Топик Main = `week_theme(week_start)` (LLM дописывает подвопросы/вокабуляр/stretch/wrap-up вокруг темы).
- `build_card_message` рендерит 4 фазы с заголовками и таймингами.
- Рендер терпим к старым карточкам без `stretch_challenge`/таймингов (`.get()` с дефолтами).

## Fallback / ошибки

- LLM упал → банк тем + банк вопросов (текущее поведение сохраняется).
- `stretch_challenge` не сгенерился → дефолтный по типу из шаблона.

## Тесты

- Юниты:
  - `week_theme` детерминирован и не повторяется в пределах банка;
  - `submit_poll` отклоняет прошедший день (`past_day`), пропускает сегодня/будущее;
  - `build_weekly_poll_card` не рендерит кнопки для прошедших дней;
  - `stretch_challenge` заполнен для всех типов (template + LLM fallback);
  - карточка рендерится 4 фазами.
- e2e: голос за прошедший день → `ok: False`.

## Порядок реализации

1. `week_theme.py` + тесты.
2. Вопросы недели (тема в персональный, банк+ротация общий) + тесты.
3. Запрет прошедших дней (сервер + карточка) + тесты.
4. 4-фазный план карточки (структура + stretch + рендер) + тесты.
5. Прогон.

## Подводные камни

1. **Тайминг темы**: вопросы раньше карточки → тема детерминирована по `week_start`, оба согласованы без хранилища.
2. **«Общий без повторов»**: повторы считаем глобально по неделе (банк большой), не персонально — иначе вопрос перестанет быть «общим».
3. **Прошедший день** — по таймзоне приложения, не UTC.
4. **Смена структуры контента** ломает старые `cards.content` — рендер должен терпеть отсутствие `stretch_challenge`/таймингов.
