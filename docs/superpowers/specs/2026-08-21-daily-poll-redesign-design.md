# Дизайн: ежедневное голосование за время встречи (вместо недельного опроса)

> Дата: 2026-08-21. Статус: согласовано с владельцем. Владелец: Кирилл.

## 1. Контекст и проблема

Сейчас бот работает по недельному циклу: в понедельник создаёт `weekly_polls`, рассылает опрос, по дедлайну выбирает слот. Реальный опыт показал, что это неудобно и местами сломано (дедлайн в прошлом, парсинг add-on, перестановка вопросов). Владелец хочет перейти на ежедневный цикл: каждое утро группа отвечает «кто сегодня и во сколько», к обеду бот решает, организовывать ли встречу сегодня и на какое время.

## 2. Требования (согласовано)

1. **Ежедневный цикл.** Опрос приходит **каждый день** в 9:00, люди отвечают до 14:00, в 14:05 бот финализирует.
2. **Группа одна.** Бот состоит ровно в одном пространстве Google Chat. Мульти-групповой логики нет. `space_id` уже хранится в `config`.
3. **Три слота времени** — 15:00 / 16:00 / 17:00, единые (не настраиваются).
4. **Один выбор на человека.** Участник указывает одно время или «не могу сегодня».
5. **Порог 3 человека.** Время с ≥3 голосами формирует встречу.
6. **Разделение на группы.** Каждое время, набравшее ≥3, даёт отдельную встречу (до трёх встреч в день).
7. **Недобор времени.** Людям, чьё время набрало <3, предлагают присоединиться к самому популярному состоявшемуся времени.
8. **Пустой день.** Если ни одно время не набрало 3 — встреча отменяется, бот сообщает в группу.
9. **Онбординг в личку.** При добавлении бота в группу анкета НЕ шлётся в группу. Вместо этого:
   - у кого есть DM с ботом и не пройден онбординг → анкета в личку;
   - у кого нет DM → @упоминание в группе с просьбой написать боту.
10. **Повторный клик** перезаписывает голос (одно время на человека).
11. **Голос после дедлайна** отклоняется («голосование закрыто»).

## 3. Модель данных

Переиспользуем существующую схему, переосмыслив «неделю» в «день».

### 3.1. `weekly_polls` → `daily_polls`

- Переименовать таблицу `weekly_polls` → `daily_polls`.
- Переименовать `week_start` → `poll_date` (DATE), `unique` остаётся на этом столбце (один опрос в день, группа одна).
- Убрать недельные поля, которые больше не нужны: `reminder_interval_hours`, `max_reminders` (они были под недельные напоминания опроса — не используются).
- Оставить `voting_deadline`, `created_at`, `closed_at`, `status`.
- `status`: `active` → `finalized` (встреча/и определены) → `cancelled` (день без встречи).

### 3.2. `poll_slots`

Остаются. На каждый опрос создаётся 3 слота: 15:00, 16:00, 17:00 (длительность по умолчанию 60 мин, `slot_end = slot_start + 60m`). Слоты и их время задаются в `config` (ключ `daily_slots`), чтобы не хардкодить в коде.

### 3.3. `poll_responses`

Остаются. `status`: `pending` / `responded` (выбрал время) / `not_available` (не может сегодня).

### 3.4. `poll_votes`

Остаются. Один голос на человека: при повторном сабмите старые голоса удаляются, вставляется новый (логика уже есть в `submit_poll`). Триггер `update_poll_slot_votes_count` продолжает работать.

### 3.5. `meeting_instances`

Остаются, теперь несколько в день (по одной на время с ≥3). Связь с `poll_slots` через `selected_slot_id` сохраняется. Триггер `update_meeting_participants_count` продолжает работать.

### 3.6. `config`

Добавляются ключи:
- `daily_slots` — `[{"time": "15:00"}, {"time": "16:00"}, {"time": "17:00"}]`.
- `quorum_threshold` — `3` (порог участников; уже есть в сидинге).
- `poll_run_hour` / `poll_run_minute` — `9` / `0`.
- `poll_deadline_hour` / `poll_deadline_minute` — `14` / `0`.
- `poll_finalize_hour` / `poll_finalize_minute` — `14` / `5`.
- `meeting_duration_minutes` — `60`.

## 4. Поток

### 4.1. Онбординг (`ADDED_TO_SPACE`)

1. Запомнить `space_id` в `config`.
2. `list_space_members(space_id)` → участники.
3. Для каждого участника:
   - профиль есть И `chat_space_id` (DM) есть И `onboarding_completed = false` → отправить анкету в DM (`send_message` в DM).
   - иначе (нет DM) → собрать в список для @упоминания.
4. Если список новичков непуст → одно сообщение в группу с @упоминаниями: «@user1 @user2 — напишите боту в личку, чтобы пройти короткую анкету».

### 4.2. Ежедневный опрос (cron 9:00)

1. Прочитать `space_id` из `config`. Если пуст — пропустить (бота не добавили).
2. Создать `daily_polls` на сегодня (`poll_date = today`, `status = active`, `voting_deadline = today 14:00`).
3. Создать 3 `poll_slots` из `config["daily_slots"]`.
4. Отправить карточку в группу (`space_id`): заголовок «Кто сегодня и во сколько?», кнопки 15:00 / 16:00 / 17:00 и «не могу сегодня».

### 4.3. Голосование (до 14:00)

Клик по кнопке → вебхук → `submit_poll`:
- если уже `responded` — удалить старые голоса, записать новый (одно время);
- кнопка «не могу» → `status = not_available`;
- после 14:00 → отклонить («голосование закрыто»).

### 4.4. Финализация (cron 14:05)

1. Взять опрос дня, посчитать голоса по слотам (`poll_slots.votes_count`).
2. Слоты с `votes_count >= quorum_threshold` (3) → для каждого создать `meeting_instances` (scheduled на это время) и отправить в группу сообщение «Встреча сегодня в 15:00».
3. Слоты с `votes_count < 3` → собрать их участников и отправить им предложение присоединиться к самому популярному из состоявшихся времён.
4. Если состоявшихся времён 0 → пометить опрос `cancelled`, сообщить в группу «Сегодня встреча не набирается — отмена».
5. Пометить опрос `finalized`.

## 5. Сценарии выбора времени

| Голоса по слотам | Результат |
|---|---|
| 15:00=3, 16:00=2, 17:00=1 | встреча в 15:00; участникам 16:00 и 17:00 предложить 15:00 |
| 15:00=3, 16:00=4, 17:00=3 | три встречи: 15:00, 16:00, 17:00 |
| 15:00=2, 16:00=2, 17:00=2 | ни один ≥3 → отмена дня |
| 15:00=5, 16:00=0, 17:00=0 | одна встреча в 15:00 |

## 6. Крайние случаи

- Повторный клик → перезапись (одно время).
- Голос после дедлайна → отклонён.
- Пустой день (0 голосов) → отмена дня.
- `space_id` пуст → cron пропускает (бот ещё не добавлен).
- Один и тот же пользователь в двух сценариях не существует (одно время на человека).

## 7. Что НЕ входит в этот этап

- LLM-вопросы (`poll_questions`, `llm_questions.py`) — не используются в ежедневном цикле. Оставляем код, но не подключаем.
- Банк вопросов (`question_bank.py`) — не используется (опрашиваем только время).
- Лидерборд/баллы (`leaderboard_ledger`), активности ENG-8 — вне этого этапа.
- Напоминания между 9:00 и 14:00 — не делаем (YAGNI, можно добавить позже).

## 8. Тестирование

- Юнит: парсинг add-on `formInputs`, выбор времени по сценариям таблицы (чистая функция `resolve_day_result`).
- Юнит: `submit_poll` — перезапись голоса, `not_available`, отклонение после дедлайна.
- Интеграция: cron-джобы создания/финализации на поднятом Postgres.
- Вебхук: клик по кнопке времени и «не могу» (ASGI-тест, как `test_click_webhook.py`).
