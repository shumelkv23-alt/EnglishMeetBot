# Фичи: ежедневное голосование «в тот же день» и автопланирование встреч

> Что делает эта ветка. Схема БД меняется одной миграцией `0002_daily_polling.py`
> (`alembic upgrade head`). Перестали существовать выбор дня недели, эскалации и
> решение «на завтра» — вместо них ежедневный цикл «придёшь сегодня? → время → встреча».

## Ключевые факты (как работает сейчас)

- **Таймзона бота — Москва (UTC+3).** «Сегодня» и все проверки считаются в
  `Europe/Moscow` (настройка `APP_TZ`). В сообщениях время рендерится через `astimezone`.
- **Только будни (Пн–Пт).** В выходные бот ничего не рассылает и не финализирует.
- **Три слота времени:** 15:00–16:00, 16:00–17:00, 17:00–18:00 (константы в
  `poll_logic.py`, не в config).
- **Квота на слот — 4 человека.** Слот, набравший ≥ 4 голосов, становится встречей.
  До 3 встреч в день (по числу слотов).
- **Активность и тему подбирает Кирилл** — пока заглушка `activity.py` возвращает
  `None`, в анонсе пишется «активность и тема уточняются».
- **Баллы (3 за посещение) — НЕ трогаем.** Чек-ин только фиксирует факт присутствия
  в `attendance`, начислений в `leaderboard_ledger` нет.

## Как работает полный цикл

1. **Пн–Пт 9:00 (МСК)** — бот создаёт опрос на сегодня и рассылает каждому, у кого
   есть DM с ботом, карточку «Сможешь сегодня прийти?» [Да / Нет].
2. **До 13:00** — участник отвечает:
   - «Да» → приходит карточка выбора **одного** времени (радио-кнопки 15/16/17).
     Переголосовать можно сколько угодно — новый слот заменяет старый.
   - «Нет» → «Ок, жаль 🙌».
   - Слово-триггер **«голосование»** → карточка «Сможешь сегодня прийти?» (если опрос
     ещё активен, иначе «сегодня уже закрыто»).
3. **Пн–Пт 13:00 (МСК)** — финализация: каждый слот с ≥ 4 голосов → отдельная встреча.
   В общую группу пишется анонс (время + место + активность/тема), ставится напоминание
   за 1 час. Кворум не собран ни в одном слоте → **тишина, ничего не пишем и не сохраняем**.
4. **За 1 час до встречи** — напоминание в личку участникам конкретной встречи.
   Напоминания не теряются при рестарте (восстанавливаются из встреч `scheduled`).
5. **Пн–Пт 18:00 (МСК)** — всем, кто должен был прийти, в личку уходит чек-ин
   «Ты был(а) на встрече 15:00–16:00?» [Да / Нет]. Ответ сохраняется в `attendance`
   (`source='self_checkin'`, `present`/`absent`). Баллы не начисляются.

## Уведомления: DM + группа

Анонс встречи уходит **в общую группу** (если задан `CHAT_GROUP_SPACE`). Карточки
голосования, времени и чек-ина уходят **в личку**. Пока группа не создана — оставь
`CHAT_GROUP_SPACE` пустым (анонс никуда не падает, ошибок нет).

## Модель данных (миграция `0002_daily_polling.py`)

Переиспользуем существующие таблицы — теперь «опрос» = **один день**:

| Таблица | Смысл в дневной схеме |
|---------|----------------------|
| `weekly_polls` | 1 строка на день: `week_start` = дата дня, `voting_deadline` = 13:00, `status` active/closed |
| `poll_slots` | 3 слота на день (15/16/17, `slot_start`/`slot_end` UTC) |
| `poll_responses` | ответ «да/нет»: `status='responded'` + **новый** `will_attend BOOLEAN` |
| `poll_votes` | 1 голос на участника за выбранный слот (перезапись при переголосовании) |
| `meeting_instances` | 1 строка на состоявшуюся встречу (слот, набравший кворум); сюда Кирилл положит `activity_type`/`activity_data` |
| `attendance` | чек-ин: `source='self_checkin'`, `present`/`absent` |
| `config` | `quorum_threshold`=4, новые `daily_poll_hour`=9, `daily_poll_close_hour`=13, `daily_checkin_hour`=18 |

## Настройки (таблица config)

- `quorum_threshold` — квота на слот (4)
- `daily_poll_hour` / `daily_poll_close_hour` / `daily_checkin_hour` — 9 / 13 / 18
- `default_location` — место встречи
- `meeting_reminder_hours` — за сколько часов напоминание (1)

Плюс в `.env`:

- `APP_TZ=Europe/Moscow` — таймзона бота
- `CHAT_TEST_SPACE=spaces/XXX` — DM организатора (пока не используется)
- `CHAT_GROUP_SPACE=spaces/XXX` — общая группа (пусто — без анонсов)
