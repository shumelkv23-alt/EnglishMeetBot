# Фичи: еженедельное голосование и автопланирование встреч

> Что добавлено в этой ветке. Схема БД НЕ менялась — миграции не нужны,
> достаточно `pip install -r requirements.txt` и перезапуска бота.

## Как работает полный цикл

1. **Пн 10:00 UTC** (время настраивается в таблице `config`) — бот сам создаёт опрос
   на неделю и рассылает карточку выбора дня всем, у кого есть DM с ботом.
2. **В течение недели** — участники отмечают дни в карточке и отвечают на 2 тематических
   вопроса, жмут «Забронировать день». Переголосовать можно сколько угодно — новые дни
   заменяют старые.
3. **Ежедневно в 20:00 UTC** — бот смотрит на завтрашний день:
   - кворум набран (по умолчанию 3) → **встреча фиксируется**: запись в
     `meeting_instances`, опрос закрывается, всем проголосовавшим уходит анонс
     «завтра встреча», ставится напоминание за 1 час до начала;
   - кворума нет → эскалация организатору в DM;
   - неделя кончилась без кворума → опрос `cancelled`, финальная эскалация.
4. Напоминания **не теряются при рестарте бота** — при запуске восстанавливаются
   из незакрытых встреч.

## Новые файлы

| Файл | Что делает |
|------|-----------|
| `app/services/poll_store.py` | Вся работа с БД: создание опроса недели (`weekly_polls` + слоты Пн–Вс 13:00 UTC), приём голосов (upsert `poll_responses`, перезапись `poll_votes`, темы → `answers`), ежедневное решение через чистую логику `poll_logic`, эскалации, отмена недель |
| `app/scheduler.py` | APScheduler в lifespan: cron-джобы «создать опрос» и «решение 20:00», date-job напоминаний, восстановление напоминаний при старте |
| `tests/test_poll_vote_parse.py` | 11 тестов парсинга формы голосования (оба формата Google) |
| `scripts/test_poll_create.py` | Вручную создать опрос + разослать карточки (шлёт реально!) |
| `scripts/test_poll_vote_webhook.py` | Имитация клика «Забронировать день» на локальный вебхук |
| `scripts/test_decide_now.py` | Принудительный прогон решения «на завтра» без ожидания 20:00 |

## Настройки (таблица config, уже засеяна)

- `poll_creation_day/hour/minute` — когда создавать опрос (день в crontab-семантике: 0=вс)
- `quorum_threshold` — минимальное число участников (3)
- `default_location` — место встречи («Conference Room A»)
- `meeting_reminder_hours` — за сколько часов напоминание (1)

Плюс в `.env`: `CHAT_TEST_SPACE=spaces/XXX` — DM организатора, туда летят эскалации.
